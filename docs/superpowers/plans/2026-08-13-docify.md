# Docify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a sign-up-free, entirely free file conversion web app that runs 100% in the browser — with no VM and no server-side processing.

**Architecture:** Every conversion runs on the user's device, inside a Web Worker, on WASM/WebCodecs engines. The central component is the **Hybrid Capability Router**: it measures what the device can actually do, picks the fastest available engine for each job (WebCodecs → Canvas → wasm-vips → ffmpeg.wasm), and returns a structured, explanatory rejection when a file exceeds the device's safe budget. The server does exactly two small things: anonymous aggregate statistics (Neon) and a URL-import proxy (Render). The site remains fully functional if the backend is down.

**Tech Stack:** Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · shadcn/ui · Vitest + Playwright · wasm-vips · libheif-js · pdf-lib · pdf.js · WebCodecs + mp4box.js · ffmpeg.wasm · fflate · Comlink · Neon (Postgres) · Vercel (frontend) · Render (URL proxy)

## 0. Decisions and Principles

| Decision | Value | Rationale |
|---|---|---|
| Brand | **Docify** | Matches the repo name; the tagline covers all file types |
| Processing location | **100% client-side** | No VM → zero compute cost, zero bandwidth, full privacy |
| Auth | **None** | No login or signup. Zero funnel friction |
| Backend role | Anonymous stats + URL proxy | The backend is an *optional dependency*, never on the critical path |
| File storage | **No file ever reaches a server** | The strongest marketing claim: "Your files never leave your device" |
| Design | Monochrome, high contrast | From the reference image; blue/purple and glassmorphism are prohibited |

### Invariant principles (do not erode these)

1. **No-server-processing invariant** — no file content may be sent over the network. CI enforces this with a test.
2. **Progressive enhancement** — every tool page renders its SEO content with JavaScript disabled.
3. **Lazy engine loading** — no WASM binary is in the initial bundle; engines load only after the user selects a file.
4. **Graceful rejection** — "it failed" messages are forbidden; always `reason + concrete suggestion`.
5. **No dead UI** — every operation shows progress, an ETA, and offers `cancel`.

## 1. Hybrid Capability Router (core)

This is the heart of the project. Everything depends on it, so it is built first and carries the highest test coverage.

### 1.1 The five questions it answers

```
1. Which engines support this (from → to → op) triple?
2. Can this device actually run those engines?      (capability probe)
3. Is this file size safe on this device?           (memory budget)
4. Which option is cheapest and fastest?            (cost ordering)
5. If none work — what do we tell the user?         (structured rejection)
```

### 1.3 Capability probe — `lib/router/capabilities.ts`

```ts
import type { Capabilities } from './types'

const SIMD_PROBE = new Uint8Array([
  0, 97, 115, 109, 1, 0, 0, 0, 1, 5, 1, 96, 0, 1, 123, 3,
  2, 1, 0, 10, 10, 1, 8, 0, 65, 0, 253, 15, 253, 98, 11,
])

export function detectPlatform(ua: string): Capabilities['platform'] {
  if (/iPad|iPhone|iPod/.test(ua) || (/Macintosh/.test(ua) && 'ontouchend' in globalThis)) return 'ios'
  if (/Android/.test(ua)) return 'android'
  return 'desktop'
}

export function detectBrowser(ua: string): Capabilities['browser'] {
  if (/Firefox\//.test(ua)) return 'firefox'
  if (/Chrome\/|Chromium\/|Edg\//.test(ua)) return 'chromium'
  if (/Safari\//.test(ua)) return 'safari'
  return 'unknown'
}

export function probeCapabilities(): Capabilities {
  const ua = navigator.userAgent
  const platform = detectPlatform(ua)
  return {
    crossOriginIsolated: globalThis.crossOriginIsolated === true,
    wasmSimd: WebAssembly.validate(SIMD_PROBE),
    // deviceMemory only exists in Chromium; fall back to a conservative estimate
    deviceMemoryGb: (navigator as any).deviceMemory ?? (platform === 'desktop' ? 4 : 2),
    cores: navigator.hardwareConcurrency ?? 2,
    webCodecsVideo: typeof globalThis.VideoEncoder === 'function' && typeof globalThis.VideoDecoder === 'function',
    webCodecsAudio: typeof globalThis.AudioEncoder === 'function' && typeof globalThis.AudioDecoder === 'function',
    offscreenCanvas: typeof globalThis.OffscreenCanvas === 'function',
    createImageBitmap: typeof globalThis.createImageBitmap === 'function',
    platform,
    browser: detectBrowser(ua),
  }
}
```

> **Critical:** `probeCapabilities()` is never called from inside the router — the router receives `Capabilities` **as a parameter**. This is what makes the entire selection logic testable with plain unit tests, no browser required.

### 1.4 Memory budget — `lib/router/budget.ts`

These numbers are empirical ceilings; changing them requires real-device measurement.

```ts
import type { Capabilities, EngineId } from './types'

const MB = 1024 * 1024

/** Safe total memory budget for a browser tab, by platform. */
export function platformBudget(caps: Capabilities): number {
  if (caps.platform === 'ios') return 90 * MB      // iOS Safari kills tabs early
  if (caps.platform === 'android') return 140 * MB
  const fromMemory = (caps.deviceMemoryGb * 1024 * MB) * 0.2
  return Math.min(fromMemory, 1200 * MB)           // accounts for the wasm32 heap ceiling
}

/**
 * Expansion factor: how many multiples of the input size an engine holds in RAM.
 * ffmpeg.wasm keeps the whole input and output in MEMFS, making it the hungriest.
 */
const EXPANSION: Record<EngineId, number> = {
  canvas: 6,        // a decoded RGBA bitmap is far larger than the encoded input
  vips: 4,
  heif: 5,
  pdflib: 3,
  pdfjs: 4,
  webcodecs: 2.5,   // streams — never holds the whole file
  ffmpeg: 4.5,      // input + output + working memory
  zip: 2.5,
  libarchive: 3,
}

export function maxInputBytes(engine: EngineId, caps: Capabilities): number {
  return Math.floor(platformBudget(caps) / EXPANSION[engine])
}
```

### 1.6 Router — `lib/router/router.ts`

```ts
import { ENGINES } from '@/lib/engines/registry'
import { maxInputBytes } from './budget'
import type { Capabilities, ConversionTask, RouteResult, Warning } from './types'

const MB = 1024 * 1024

function formatBytes(n: number): string {
  if (n >= 1024 * MB) return `${(n / (1024 * MB)).toFixed(1)} GB`
  if (n >= MB) return `${Math.round(n / MB)} MB`
  return `${Math.round(n / 1024)} KB`
}

export function route(
  task: ConversionTask,
  inputBytes: number,
  caps: Capabilities,
): RouteResult {
  if (inputBytes <= 0) {
    return {
      ok: false,
      code: 'EMPTY_INPUT',
      message: 'This file is empty.',
      suggestion: 'Choose a different file.',
    }
  }

  const candidates = ENGINES
    .filter((e) => e.supports(task, caps))
    .sort((a, b) => a.priority - b.priority || a.loadCost - b.loadCost)

  if (candidates.length === 0) {
    return {
      ok: false,
      code: 'UNSUPPORTED_PAIR',
      message: `${task.from.toUpperCase()} → ${task.to.toUpperCase()} is not supported in this browser.`,
      suggestion: 'Try again in a recent version of Chrome or Edge.',
    }
  }

  const fitting = candidates.filter((e) => inputBytes <= maxInputBytes(e.id, caps))

  if (fitting.length === 0) {
    const best = candidates.reduce((a, b) =>
      maxInputBytes(a.id, caps) >= maxInputBytes(b.id, caps) ? a : b,
    )
    const limit = maxInputBytes(best.id, caps)
    return {
      ok: false,
      code: caps.platform === 'desktop' ? 'FILE_TOO_LARGE' : 'DEVICE_TOO_WEAK',
      message: `This file is ${formatBytes(inputBytes)}. The safe limit on this device is ${formatBytes(limit)}.`,
      suggestion:
        caps.platform === 'desktop'
          ? 'Split the file into parts, or reduce its size first.'
          : 'Open this on a desktop — mobile browsers have a much lower memory ceiling.',
    }
  }

  const chosen = fitting[0]
  const warnings: Warning[] = []

  if (chosen.id === 'ffmpeg' && !caps.crossOriginIsolated) {
    warnings.push({
      code: 'NO_ISOLATION',
      message: 'Running single-threaded — reload the page to enable multi-threaded mode.',
    })
  }
  if (chosen.id === 'ffmpeg') {
    warnings.push({ code: 'SLOW_PATH', message: 'No hardware acceleration available, so this will take longer.' })
  }
  if (chosen.loadCost > 8 * MB) {
    warnings.push({
      code: 'LARGE_DOWNLOAD',
      message: `Loading the engine (${formatBytes(chosen.loadCost)}) — one time only.`,
    })
  }

  return { ok: true, engine: chosen.id, reason: chosen.label, loadCost: chosen.loadCost, warnings }
}
```

### 1.7 Engine priority table

| Priority | Engine | Download | Used for | Falls back to |
|---:|---|---:|---|---|
| 10 | `canvas` | 0 KB | jpg/png/webp/gif format swaps, simple resize | `vips` |
| 15 | `webcodecs` | ~120 KB (mp4box.js) | **Video transcode — hardware accelerated** | `ffmpeg` |
| 20 | `pdflib` | ~350 KB | PDF merge/split/rotate/organize/protect | — |
| 25 | `pdfjs` | ~1.1 MB | PDF → image, PDF → text | — |
| 30 | `zip` | ~35 KB | ZIP create/extract | `libarchive` |
| 35 | `heif` | ~1.8 MB | HEIC/HEIF decode | — |
| 40 | `vips` | ~5.5 MB | AVIF, TIFF, high-quality resize, metadata | — |
| 50 | `libarchive` | ~700 KB | RAR/7z extraction | — |
| 90 | `ffmpeg` | ~32 MB | **Universal fallback** — when everything else fails | — |

**Rule:** `ffmpeg` is always the last resort. If WebCodecs is available, video must never fall through to ffmpeg.

### 2.3 Layout signature (patterns derived from the reference)

These are the project's visual fingerprint — pages are assembled from these blocks:

1. **SectionBlock** — the page is a stack of alternating light/dark full-width blocks. Each block is `rounded-[28px]` and inset `24px` from the shell background.
2. **CapabilityStrip** — a horizontal row under the dark block: `icon + title + subtitle`. The same structure as the reference's "Hi-Res Audio / Active Noise Cancellation / Bluetooth 5.3" row. Ours: `Runs in browser / No sign-up / No limits / Hardware-accelerated / Open source`.
3. **StatPair** — a large figure + small unit, with a tiny caption beneath. The reference's `50MM / Drivers`. Ours: `0 KB / sent to a server`, `<2s / average processing`.
4. **FeatureCard** — an `--color-ink-2` card on dark, `1px solid --color-line-dark`, with a `44px` circular icon badge on top (`--color-ink-3` fill), a title, and two lines of copy.
5. **Button** — primary: white fill / black text / `→` icon / `rounded-full`. Secondary: transparent with a `1px` border. **No gradients, no shadows.**
6. **Grid overlay** — very faint `1px` grid lines in the light hero section (`--color-line-light`, opacity `0.5`). Hero only, nowhere else.

### 2.4 Prohibitions (enforced in CI)

```
❌ backdrop-filter / backdrop-blur          → glassmorphism
❌ bg-gradient-* with blue/purple stops     → prohibited palette
❌ raw hex codes in CSS                     → use tokens only
❌ box-shadow used for a "float" effect     → flat surfaces + borders
❌ external font/CDN requests               → everything self-hosted
```

## 5. GitHub Workflow Rules

These rules are **mandatory** and are repeated in `CLAUDE.md`.

### 5.1 Before every task

```bash
git checkout main
git pull origin main
git checkout -b <type>/<issue-number>-<slug>
```

### 5.2 Branch naming (Conventional Branch)

| Prefix | Use |
|---|---|
| `feat/` | New functionality |
| `fix/` | Bug fix |
| `refactor/` | Structure without behaviour change |
| `perf/` | Performance |
| `docs/` | Documentation |
| `test/` | Tests only |
| `chore/` | Tooling, dependencies, CI |

Example: `feat/42-webcodecs-video-engine`

### 5.3 Commits (Conventional Commits)

```
<type>(<scope>): <short description>

<optional body>

Refs #<issue>
```

Example: `feat(engines): add WebCodecs video transcode path`

> **CRITICAL:** Commit messages must contain **no** `Co-Authored-By: Claude`, `Generated with Claude Code`, `🤖`, or any other AI attribution. No bot may appear in the contributors list. Every commit is authored solely by the repository owner.

### 5.4 Issue rules

- Every issue is **assigned to `ismetcahangirov`**
- Minimum labels: `type:*`, `area:*`, `priority:*`
- Epics carry the `type:epic` label and link their children as **GitHub native sub-issues**
- Issues close only via a merged PR (`Closes #N`)

### 5.5 Label taxonomy

```
type:epic  type:feat  type:fix  type:refactor  type:perf  type:docs  type:test  type:chore
area:router  area:engine  area:ui  area:design  area:seo  area:perf  area:a11y
area:backend  area:ci  area:agent
priority:p0  priority:p1  priority:p2
status:blocked  status:needs-review  status:ready
size:xs  size:s  size:m  size:l
```

### 5.6 PR & merge

1. Open a PR with `Closes #N` in the body
2. All five CI jobs (lint, typecheck, unit, e2e, build) must be **green**
3. The Lighthouse CI gate must pass for UI changes
4. **Squash merge** into `main`
5. The branch is deleted automatically

## 6. Recommendations

1. **WebCodecs is your real advantage.** Commercial converters gate GPU encoding behind a paid tier. Routing to WebCodecs gives every user hardware acceleration for free, on their own device. Make it a marketing message: *"Hardware-accelerated. Free. Always."*
2. **"Your files never leave your device" is a position competitors cannot copy.** Their business model depends on server-side processing. Put this above the fold on the homepage.
3. **Spend the first three months on SEO.** The code being finished means nothing without traffic. Each of the 120 pages needs genuinely unique FAQ and instruction copy — templated duplicates get penalised.
4. **Start with `size:xs` tasks.** The first merged PR should be the CI setup, because everything after it depends on that.
5. **Measure on real devices.** The numbers in `budget.ts` are estimates. After the first release, collect telemetry on real OOM events and recalibrate the ceilings.
