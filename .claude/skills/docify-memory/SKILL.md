# Docify Agent Memory

A repository-scoped memory system modelled on claude-mem. Facts live as markdown in the repo, so they are versioned, reviewable and portable — no external service.

```
.claude/memory/
  MEMORY.md        index, committed, injected at session start
  entries/*.md     one durable fact per file, committed
  sessions/*.jsonl raw observations, gitignored
  index.db         SQLite FTS5 cache, gitignored, rebuildable
```

## Progressive disclosure

Session start injects **descriptions only** — roughly 30 tokens per entry. Never dump the whole memory into context. The flow is always:

```
1. search   → compact hits (~50 tokens)
2. get      → the full entry, only for what you actually need (~300 tokens)
```

## Commands

```bash
node --no-warnings .claude/hooks/memory-cli.mjs search "webcodecs fallback"
node --no-warnings .claude/hooks/memory-cli.mjs get ios-memory-ceiling
node --no-warnings .claude/hooks/memory-cli.mjs list decision
node --no-warnings .claude/hooks/memory-cli.mjs write decision <name> <description> <body>
node --no-warnings .claude/hooks/memory-cli.mjs reindex
```

## When to search

- Before changing a value that looks arbitrary (a budget, a priority, a threshold)
- Before re-litigating an approach — it may already have been tried and rejected
- When a test fails in a way that smells like a known platform quirk
- At the start of any task touching `lib/router/` or `lib/engines/`

## When to write

Write an entry when the **rationale would be invisible to someone reading the code**.

| Type | Use for | Example |
|---|---|---|
| `decision` | An architectural choice and why the alternatives lost | Why WebCodecs is preferred over ffmpeg.wasm for video |
| `constraint` | A hard limit discovered by measurement | iOS Safari kills tabs above ~90 MB |
| `gotcha` | Non-obvious behaviour that cost debugging time | `VideoEncoder` exists but the codec may still be unsupported |
| `reference` | External resource worth returning to | Link to the WebCodecs codec-registry spec |
| `session` | Auto-generated by the SessionEnd hook | — |

## Do not write

- Anything the code already states clearly
- Anything git history already records ("fixed bug X in commit Y")
- Task-local detail that stops mattering when the task ends
- File contents, secrets, or user data

## Entry format

```markdown
---
name: ios-memory-ceiling
description: iOS Safari terminates tabs above roughly 90MB of WASM heap
type: constraint
date: 2026-08-13
---

Measured on iPhone 13 / iOS 17 and iPhone 15 / iOS 18. ffmpeg.wasm reliably
crashes the tab when input x expansion factor exceeds ~90MB.

This is why `platformBudget()` in `lib/router/budget.ts` hardcodes 90MB for iOS
rather than deriving it from `navigator.deviceMemory` — Safari does not expose
`deviceMemory` at all, and the observed ceiling is far below what the device
nominally has.

Related: [[webcodecs-over-ffmpeg]]
```

Link related entries with `[[entry-name]]`. A link to an entry that does not exist yet is fine — it marks something worth writing later.

## Maintenance

- Before adding an entry, `search` for one that already covers it — update rather than duplicate
- Delete entries that turn out to be wrong; a stale constraint is worse than no constraint
- Entries record what was true when written. Verify any file, symbol or flag they name still exists before acting on it
- `index.db` is disposable — run `reindex` if search behaves oddly
